# RedBuddy 排错

按「症状 → 原因 → 怎么办」排。先看第一节，它覆盖了最高频的三个。

---

## 0. 先看日志

```bash
tail -40 ~/RedBuddy/.logs/redbuddy.log
```

服务每次请求都会打一行日志，绝大多数问题看一眼日志就定位了。
如果日志里出现 `Agnes 用量：prompt=… completion=…`，说明那一步**真的调了模型**。

---

## 1. `连不上 api.agnes-ai.cn：fetch failed` ★ 最高频

**原因**：Node 的 `fetch` 会走 `HTTP_PROXY` / `HTTPS_PROXY` 环境变量。
经代理访问 Agnes 时 TLS 证书校验失败（代理换的证书里没有域名），
真实原因被藏在 `e.cause` 里，表面只看到 `fetch failed`。

**典型症状**：RedFox 正常（代理放行），只有 Agnes 挂。

**怎么办**：

```bash
# 先确认 shell 里有没有代理变量
env | grep -i proxy

# 有的话，起服务时清掉
env -u HTTP_PROXY -u HTTPS_PROXY -u http_proxy -u https_proxy node server.js
```

`scripts/start.sh` 已经自动处理了。**用双击 `.command` 起的服务最容易踩这个**
（`.command` 继承的是终端环境）。

想验证到底是不是代理的锅：

```bash
env -u HTTP_PROXY -u HTTPS_PROXY -u http_proxy -u https_proxy \
  node -e "fetch('https://api.agnes-ai.cn/v1/models').then(r=>console.log('OK',r.status)).catch(e=>console.log('FAIL',e.cause&&e.cause.code))"
```

打印 `OK` 就是代理问题，打印 `FAIL ERR_TLS_...` 就是证书问题（同一件事）。

---

## 2. 起不来 / 端口被占用

**症状**：`EADDRINUSE`，或者 `start.sh` 说端口已被占用。

```bash
lsof -ti:8090 | xargs kill    # 停掉占用 8090 的进程
bash scripts/start.sh
```

想换端口：改 `config.local.json` 里的 `port`，然后重启。

---

## 3. 改了后端代码不生效

`server.js` / `collector.cjs` / `providers.cjs` / `neterr.cjs` 都是**启动时加载**的，没有热重载。
改完**必须重启服务**，否则改了个寂寞，而且症状很有迷惑性（比如「设置里的 Key 不生效」）。

`index.html` 是每次请求现读磁盘的（带 `Cache-Control: no-store`），改完**刷新页面**即可。

---

## 4. 密钥类报错

工具会把数据源的错误码翻译成人话：

| 提示 | 含义 | 怎么办 |
|---|---|---|
| 免费次数用完了 | 这个账号的免费额度用尽 | **换个新邮箱再注册一个账号**（红狐注册即送 200 积分；Agnes 邮箱注册即可免费用），把新密钥填进来；也可以配多把 Key 用「顺序轮换」 |
| Key 无效 / 已失效 | 密钥写错了或过期 | 核对密钥（注意别多复制空格） |
| Key 已被禁用 | 在控制台被停用 | 启用它，或换一把 |
| 触发限流 | 请求太密 | 稍等重试；配多把 Key 用「顺序轮换」 |

**注意**：密钥只在浏览器「设置」页里配，**服务端不读环境变量、不读配置文件**。
如果你在 `config.local.json` 或 `.zshrc` 里写了 key，**它是不会生效的** ——
这是故意的设计（历史上被 stale 的旧 key 静默带偏过好几次）。

---

## 5. 短链打不开 / 提示「优质库未收录」

- **必须用分享短链**（`xhslink.cn/o/xxx`），不能只给 24 位笔记 ID。
- 「优质库未收录」不是错误 —— 只是那家库没这条笔记，工具会**自动降级**用另一个接口的数据，
  **不报错也不影响结果**。
- 同一篇笔记偶尔取不到，多半是短链过期了，回 App 重新复制一条。

---

## 6. 视频放不出来

**直链是带时效的临时通行证**，过期就播不了。

- 回「爆款拆解」用当初那条短链**重新解析**（拆解库里存了这条短链，直接搜就能找到）
- 另外：视频是实时从小红书 CDN 拉的流，网络不通畅也会卡

---

## 7. 拆解报「JSON 解析失败 / 模型输出不合法」

Agnes 没有 JSON 模式，模型有一半概率把 JSON 写坏（套代码块、写裸换行、多写一个括号…）。

工具已经做了**自愈修复 + 自动重试 1 次**（温度降到 0.1）。两次都不行才报 502，
并把模型原文落盘到**系统临时目录**（`os.tmpdir()` 下的 `redbuddy-decompose-raw-*.txt`）供排查。

**怎么办**：再点一次。偶尔两次都失败是模型的问题，不是工具坏了。

---

## 8. 封面出图慢 / 失败

- 单张 1K 出图约 **10–60 秒**，期间**别关页面**。
- 出图失败会记进结果列表并提示第一条错误，**不会中断整批**。
- 想要风格样图但不想重新出图？**12 张真实样图已经内置**，开箱就有。
- 如果某一张不满意，卡片上有 **「重出」** 按钮（鼠标移上去才显示），
  只重跑那一张，不用为一张图重跑 12 张。

---

## 9. 不联网自检（先确认工具本身装对了）

1. 打开 `config.local.json`
2. `"xhsProvider"` 改成 `"mock"`
3. 重启服务 → 这时不联网也能跑通「贴链接 → 取到内容」这一段
4. **验证完记得改回 `"redfox"`**

`mock` 故意不出现在界面上，只能在配置文件里指定 —— 免得手滑切过去后一脸懵。

---

## 10. 页面空白 / 按钮点了没反应

1. **强刷**：`Cmd+Shift+R`（`index.html` 不带缓存，但浏览器可能还留着旧的 JS 状态）
2. 打开浏览器控制台看有没有红色报错
3. 确认服务在跑：`curl http://127.0.0.1:8090/healthz`，返回 `{"ok":true,...}` 就是活着

`/healthz` 会打印当前生效的数据源、模型名和路由表，排查时很好用。
