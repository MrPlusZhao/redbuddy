# RedBuddy · 小红书洞察工具

本地运行的小红书内容提取 / 分析工具。

## 能做什么

左侧导航有六个入口：**爆款拆解** / **我的拆解库** / **封面制作** / **标题生成** / **设置** / **使用说明**。

| 功能           | 说明                                                                                                                        |
| ------------ | ------------------------------------------------------------------------------------------------------------------------- |
| **① 解析短链**   | 贴一条小红书分享短链（或整段分享文案），取回：标题 · 正文全文 · 配图 · 点赞/收藏/评论 · 作者 · 发布时间                                                              |
| **② 视频转写**   | 视频笔记再走 RedFox 服务端转写，出口播逐字稿                                                                                                |
| **③ 自动拆解报告** | 上面两步做完**自动**交给 Agnes 出 8 节拆解报告，直接打开报告页（需 Agnes Key）                                                                       |
| **④ 去仿写**    | 报告页右上角「去仿写」→ 基于这份报告出标题备选 / 仿写正文 / 封面建议（复用报告里已有结果，不重新调模型）                                                                  |
| **我的拆解库**    | 拆解出的报告都存这里，点卡片随时回看完整报告；支持搜索、排序、两段式删除                                                                                      |
| **⑤ 封面制作**   | 按「内容 → 标题 → 风格 → 构图 → 叠字」填表，一键出 3:4 小红书封面（**Agnes 出图**）。内置 12 种原创风格 + 6 套配色 + 8 种构图                                       |
| **⑥ 标题生成**   | 填一句主题（或贴一条现成标题），按 `space-xhs-title` 的流程批量出标题：**12 / 20 个候选 · 至少 6 种方法 · 带字符数、评分、风险 · Top5 按用途分角色 · 给 A/B 建议**（Agnes 对话模型） |
| **使用说明**     | 一页讲清两个账号怎么用邮箱免费注册、密钥填在哪、每个页面怎么用、常见问题                                                                                      |

「爆款拆解」页只有**解析短链**这一个入口 —— 取回原文后**不在页面里渲染结果卡，而是直接进报告页**  
（原来并排的「粘贴文案评分」已按需求去掉，它的评分维度被拆解报告完全覆盖）。


### 我的拆解库

报告页右上角点 **「存入拆解库」** 才入库（左侧菜单，键 `redbuddy.decompose.v1`，只存在这台电脑的浏览器里）。

- 每条记录存：封面 / 标题 / 作者 / 标签 / 互动数 / **爆款指数**（五维评分均值）/ 保存时间，以及**完整拆解结果**——  
  所以点开卡片是**直接渲染**，不会重新调 Agnes。
- 还存**当初粘贴进来的那条分享链接**（`shareUrl` / `shareText`）：
  - 卡片底部显示截短后的链接，鼠标移上去出现「复制」按钮；
  - 报告页顶部也有一条「分享短链」，带「复制」和「打开」；
  - **搜索框可以直接粘短链**来定位这条记录。
  - 为什么要存：视频直链是带时效的，过期后想重新解析这条笔记时，不用再回 App 里重新复制一次链接。  
    （旧记录没有这个字段 → 那一行不显示，不影响打开。）
- 列表支持**按关键词搜索**（标题 / 作者 / 短链）、**按时间 / 分数排序**；删除是**两段式**（点「删除」变「确认删除」，3 秒内再点才真删）。
- 报告页共 8 节：`01封面分析 02标题拆解 03正文结构 04标签策略 05互动率判断 06爆款因子 07风险点 08需求与任务`。  
  仿写（标题备选 / 仿写正文 / 封面建议）不在报告里，是独立一页（报告右上角「去仿写」进）。
- 报告在 8 节**之前**固定放一个 **「原始素材」区块**（默认展开），把拆解时拿到的东西原样留着：  
  **笔记正文** + **文案描述**（视频笔记的口播逐字稿，只留连续文案，不再展示带时间戳的分段）+ **配图**。  
  这些素材在 `Report.build` 时一并存进记录，所以**从「我的拆解库」重开报告时素材还在**（重开不会重跑转写）。
- **视频不放这里**，走报告顶部封面上的 ▶ 按钮 → 居中弹窗播放（见下面「视频和图片存在哪里」）。
- 报告 8 节与「原始素材」区块**默认全部展开**，右侧折叠按钮做成明显的**胶囊样式**（「收起」/「展开」可点切换），一眼能找到。

> 长任务（提取 / 转写）的**分步进度**由前端自己维护（`naFlowSet`，竖排三步、跑动时浮在屏幕正中央），  
> 不轮询后端。等待期间还会轮播一句文案提示 + 显示已等待秒数。

> 视频转写 2026-10 起**只走 RedFox 服务端**（`audioTextExtract`：submit → 轮询 result，  
> 不占本机算力）；早期那套「本机 ffmpeg + 本地 Whisper」链路已整体移除。  
> `server.js` 里早期的 `/api/redfox/*` 旧路由也已一并删除。

## 视频和图片存在哪里

**都不在本机。** 本机只存「地址」，不存「文件」。

| 东西             | 实际在哪                                                                                                                 |
| -------------- | -------------------------------------------------------------------------------------------------------------------- |
| 视频文件本身         | **小红书的 CDN**（`sns-video-*.xhscdn.com`）。RedFox 的 `parseWork/parse` 只返回一个**直链**，页面播放时是**实时从 CDN 拉的流**                  |
| 图片 / 封面        | 同上，小红书图片 CDN（`sns-img-*.xhscdn.com`）                                                                                 |
| 那条**直链**       | 存在**浏览器 `localStorage`** 里 —— 「我的拆解库」的记录字段 `videoUrl` / `images`（键 `redbuddy.decompose.v1`）。所以从拆解库重开报告时 ▶ 还在，不用重新调接口 |
| 你当初粘贴的**分享短链** | 同样存在拆解库记录里（`shareUrl` / `shareText`）—— 直链过期后靠它重新解析这条笔记                                                               |
| 当前会话的原始 note   | 只放内存（`SRC` 对象），刷新页面就没了                                                                                               |

**服务端不落盘**：媒体代理 `proxyMedia()` 是 `Readable.fromWeb(up.body).pipe(res)` —— 边拉边转发给浏览器，  
没有任何 `writeFile` / `createWriteStream`，响应头还带 `Cache-Control: no-store`。

> ⚠️ 唯一可能在你磁盘上留下临时副本的是**浏览器自己的 HTTP 缓存**：视频直连 CDN 时，  
> 缓存策略由 CDN 返回的响应头决定，Chrome 可能把视频片段存在自己的缓存目录里（临时、会自动淘汰）。  
> 想彻底不留，可以在 Chrome DevTools 的 Network 面板勾上 Disable cache，或改用代理路径播放。

> ⚠️ **直链是带时效的**，它只是一张「临时通行证」，不是视频本身。过期后播放会失败，  
> 只能回「爆款拆解」重新解析这条笔记拿新链接。

## 快速开始

**前置：装 Node.js 18 或更高版本**（[nodejs.org](https://nodejs.org) 下 LTS 版即可）。  
本项目**零第三方依赖**，不需要 npm install、不需要 Playwright / ffmpeg / 本地 Whisper。

### macOS

```bash
# 首次
双击「安装依赖.command」      # 无第三方依赖，只做环境校验
# 以后
双击「启动.command」          # 或  node server.js
```

### Windows

```bat
首次   双击「安装依赖.bat」   :: 只做 Node 版本校验
以后   双击「启动.bat」       :: 或在本目录开 cmd 跑  node server.js
```

> 两个 `.bat` 会自己 `chcp 65001`（中文不乱码）、清掉 `HTTP(S)_PROXY` 环境变量  
> （**必须清** —— 见下面「代理变量」一节），并在 2 秒后自动打开浏览器。  
> **启动窗口就是服务本身，关掉窗口 = 停止服务。**

### Linux

```bash
node server.js        # 记得先清代理变量，见下面「代理变量」一节
```

然后打开 <http://127.0.0.1:8090/> ，直接贴链接即可 —— 不需要登录、不需要扫码。

### 平台兼容性

| 项目              | 状态                                                                                                               |
| --------------- | ---------------------------------------------------------------------------------------------------------------- |
| Node 代码（4 个 js） | ✅ 全平台。无 `child_process`、无平台分支，路径全走 `path.join(__dirname, …)` 和 `os.tmpdir()`                                     |
| 中文字体            | ✅ 字体栈里已带 `Microsoft YaHei`（Windows）/ `PingFang SC`（macOS），封面叠字不会乱码                                               |
| 复制到剪贴板          | ✅ 优先 `navigator.clipboard`，非安全上下文（如局域网 HTTP）自动降级到 `execCommand`                                                  |
| 启动脚本            | ⚠️ `启动.command` 仅 macOS；Windows 用 `启动.bat`（已提供，功能对齐）                                                             |
| 手机浏览器           | ⚠️ 前端已适配（`@media max-width:760px`），但服务默认只监听 `127.0.0.1`，手机连不上 —— 需改 `config.local.json` 的 `host` 为 `0.0.0.0` 并重启 |

### ⚠️ 代理变量

Node 的 `fetch` 会走 `HTTP_PROXY` / `HTTPS_PROXY`。如果这两个变量指向一个本地代理，  
访问 `api.agnes-ai.cn` 会 **TLS 证书校验失败**，症状是「连不上：fetch failed」——  
而 RedFox 却正常，很容易误判成 Agnes 的问题。

两个 `.bat` 已自动清掉这些变量；手动跑 `node server.js` 时请自己确认：

```bash
# macOS / Linux
env -u HTTP_PROXY -u HTTPS_PROXY -u http_proxy -u https_proxy node server.js
```

## 重要：必须用「分享短链」

数据源是按链接（或链接里的笔记 ID）取内容的，**只用笔记 ID 不一定打得开**：

- ✅ `https://xhslink.cn/o/xxxxx`（App 里「复制链接」得到的）
- ✅ 整段分享文案（会自动从中抠出链接）
- ⚠️ 只有 24 位笔记 ID：RedFox 有时能试，取不到就回 App 重新复制链接

## 数据源

数据源在 `config.local.json` 里配置，**改完要重启服务**。适配层在 `providers.cjs`，把厂商的接口差异收敛成统一结构，上层（`collector.cjs` / `server.js`）不关心用的哪家。

| `xhsProvider` | 数据源                    | 需要登录  | 账号                              |
| ------------- | ---------------------- | ----- | ------------------------------- |
| `redfox`      | RedFox 红狐（`redfox.hk`） | ❌ 不需要 | **邮箱注册即送 200 积分**，用完换新邮箱再注册一个即可 |
| `mock`        | 本机假数据（**隐藏**，不在界面出现）   | ❌ 不需要 | 不需要账号，完全离线，仅供自检                 |

| 字段             | 默认       | 说明                                                       |
| -------------- | -------- | -------------------------------------------------------- |
| `xhsProvider`  | `redfox` | 见上表。**留空、或填 `local` / `tikhub` / `rnote` 都会报错** —— 都已被移除 |
| `xhsBase`      | 厂商默认     | 一般留空；自建代理时才填                                             |
| `mockVideoUrl` | 空        | 可选，只有 `xhsProvider: "mock"` 时才用得上（见上表）                   |

也可用环境变量覆盖：`XHS_PROVIDER` / `XHS_API_BASE` / `MOCK_VIDEO_URL`。

> ★ **配置文件里不写密钥**：RedFox / Agnes 的 Key 只在浏览器「设置」页里配（存 `localStorage`），  
> 随请求带给本机后端；服务端**不读环境变量、不读 `config.local.json`、不落盘**。没配就返回 400，提示去设置里填。  
> 历史包袱：以前支持 `config.local.json` / 环境变量兜底，结果被 stale 的 Key 静默带偏过好几次  
> （曾有一个已失效的旧 `REDFOX_API_KEY` 一直盖住新 Key，表现为「明明换了新 Key 还是报错」），  
> 2026-10-06 整体移除，只留「设置页」一条来源。

### 数据源不再在界面上暴露

**设置页原来那张「小红书数据源」卡片已整体移除**（2026-10-08）。现在只有 RedFox 一家，  
让用户在界面上「选」一个唯一选项没有意义，反而多一块要维护的 UI。

- 生效的数据源一律跟随后端 `config.local.json` 里的 `xhsProvider`（默认 `redfox`）。**改完要重启服务。**
- 前端仍会在启动时 `GET /api/xhs/providers` 读回 `current`，并随每次提取 / 转写请求带上  
  `provider` 字段 —— 所以后端换源（比如临时切 `mock`）不需要改前端。
- 想切到隐藏的 `mock`（离线自检）：改 `config.local.json` 的 `xhsProvider` 为 `"mock"`，重启。

### 红狐密钥（可配多个）

**设置 → RedFox 红狐密钥**：

- 可以加**多个 Key**（别名 + 值 + 启用/停用 + 上移下移），存在浏览器 `localStorage`，只在请求时传给本机后端。
- **轮换策略**：`优先使用`（总用第一个）/ `顺序轮换`（每次换下一个，适合分摊）/ `随机`。
- Key **只存在浏览器「设置」页**（`localStorage`，键 `redbuddy.redfox.v1`），服务端不持有、无任何兜底。  
  一个都没填时，提取 / 转写会直接返回 400 提示去设置里配。
- 报错提示会区分原因：**免费额度用完 / Key 无效 / 被禁用 / 限流**，并给出对应出路（换新邮箱注册 / 换 Key）。

**红狐是怎么取数的（适配层已处理）**：

分工是「**RedFox 取元数据 + 服务端转写**」。需要两个接口配合（各消耗一次调用）：

- `POST /story/api/parseWork/parse` → `awemeType` / `title` / `videoUrl`（**视频无水印直链**）/ `imageUrls`（图片直链列表）
- `POST /story/api/xhsUser/queryWorkDetail` → `workTitle` / `workDesc` / 互动数 / `coverUrl` / 作者（「优质库」，未收录返回 `code 3203`，**不消耗积分**，自动降级不报错）

视频笔记的逐字稿走 `/api/xhs/transcribe`（RedFox 服务端 `audioTextExtract`：submit → 轮询 result）。  
⚠️ **配图**：图文笔记的**完整图片直链列表**就来自 `parseWork/parse` 的 `imageUrls`（报告里「配图（N 张）」显示的就是它）。只有该字段为空时才会退回封面 1 张，并在服务端日志里打一条 warn。  
密钥只用「设置 → RedFox 红狐密钥」里配的那把（随请求以 `body.keys` 传上来），服务端不兜底。  
⚠️ **每次调用都会消耗红狐积分**，所以适配层会先把「明显不是链接」的输入拦下，并且**必须先把短链展开成完整笔记链接**再调接口（直接拿 `xhslink.cn` 短链会被拒 `3203`）。

### Agnes 密钥与「笔记拆解」

**设置 → Agnes 密钥**：同样支持多个 Key + 轮换策略，只存在浏览器 `localStorage`（键 `redbuddy.agnes.v1`），服务端不持有、无兜底。

拆解走的是 `POST /api/note/decompose`，模型 `agnes-2.5-flash`。**每次拆解约 1700 输入 + 2000 输出 token**（正文越长越多）。  
每次调用都会在日志里打一行用量：`Agnes 用量：prompt=… completion=… total=… finish=…`，方便对账。  
（`agnes-2.5-flash` 在 Agnes 上按邮箱注册即可免费使用，具体额度以你账号的权限为准。）


**⚠️ Agnes 没有 JSON 模式**：官方参数表里只有 `model / messages / temperature / top_p / max_tokens /
stream / tools / tool_choice / chat_template_kwargs / thinking`，**没有 `response_format`**，  
所以没法要求它保证输出合法 JSON。实测它大概有一半概率把 JSON 写坏，常见几种：

| 它会犯的错                                     | 我们怎么处理                              |
| ----------------------------------------- | ----------------------------------- |
| 套一层 \`\`\`json 代码块（提示词里禁了照样套）             | 剥掉                                  |
| 多段正文里写**真实换行**                            | 字符串内的裸换行/制表符转成 `\n` `\t`            |
| 写裸的强调引号：满足"我也想这样"的身份投射                    | 按「后面跟不跟结构符」判断是结束引号还是串内引号            |
| 多写一个 `}` 提前把根对象闭合                         | 判定后丢掉那个多余括号                         |
| 漏写一个 `]` / 数组元素里塞序号 `{7,"level":…}`       | 补闭合符；提示词里明确禁止写序号                    |
| 把键名写成 `[keyPoints]:`                      | 方括号里是合法标识符且后跟冒号时，还原成 `"keyPoints":` |
| `finish_reason: length` 被 `max_tokens` 截断 | 按栈补齐括号（残缺但可用），并打 `⚠` 告警             |

**自愈修不了的会自动重试 1 次**：把「你上一次的输出不是合法 JSON，错在……」连同要求重新说一遍，  
温度从 0.3 降到 0.1。两次都不行才报 502，并把模型原文落盘到**系统临时目录**  
（`os.tmpdir()` 下的 `redbuddy-decompose-raw-<时间戳>-a<次数>.txt`）供排查 —— 不往项目目录里塞文件。

> 关掉思考过程用的是 `chat_template_kwargs: { enable_thinking: false }`。  
> 以前写成顶层 `enable_thinking: false`，而官方参数表里没有这个顶层参数 —— 等于没生效，已修正。

**标注定位失败的两种情况会分开说**（不会把「模型抄歪了」说成「本来就没有」）：

- 定位成功 → 点诊断会高亮对应原文句子（一处诊断可能对应多处句子，全部点亮）。
- 有标注但跟原文对不上 → 「标注没能在原文里定位（模型抄的句子和原文不一致）」。
- 这条诊断本来就没有对应句子（数据 / 结构 / 整体判断类） → 「该条不对应原文里的具体句子」。
- 小节标题上会如实显示「另有 N 处没定位上」，不静默丢掉。

### 短链 → 视频内容（这条链路怎么走的）

```
贴分享短链
  └─ POST /api/xhs/extract { url, provider, keys, strategy }
       ├─ 数据源解析：标题 / 正文 / 互动 / **视频无水印直链 videoUrl**
       └─ 返回给前端 → 页面直接播（<video>）
  └─ POST /api/xhs/transcribe { url, keys }        ← RedFox 服务端转写
       ├─ ① submit 提交任务 → taskId
       ├─ ② 轮询 result（uploading → asr_processing → succeeded | failed）
       └─ ③ 返回 text + 分段时间戳
```

进度分四步显示（`collector.cjs` 的 `TRANS_STEPS`）：`提交任务 → 等待处理 → 语音识别 → 整理分段`。

数据源负责「给地址」与「出逐字稿」，**本机不再下载视频、不再跑本地模型**。

**离线自检这条路**（不想消耗红狐积分时用）：`config.local.json` 里把 `xhsProvider` 改成 `mock`、  
`mockVideoUrl` 指向任意可下载的视频（本机起个静态服务即可，如 `http://127.0.0.1:8123/sample.mp4`），  
重启服务后就能在完全不联网的情况下跑通「短链 → 取到视频地址」这一段。验证完记得把 `xhsProvider` 改回 `redfox`。  
`mock` 不在界面的数据源按钮里，只能在配置文件里手动指定。

**提示词在内部生成，界面上不展示。** 由 `index.html` 的 `buildPrompt()` 按固定骨架自动拼（封面文字、主体与场景 / 构图 / 风格（含光线与材质）/ 配色 / 拍摄与画质、无字 + 铺满要求、避免项），选 2 张时每张会自动追加一段「本张差异」。骨架公式：**主体细节 + 动作场景 + 风格限定 + 色彩光影 + 排版要求**。

**出图结果**：和「笔记拆解」分开调用（对话模型 / 出图模型是两条不同的链路）。点「生成封面」会弹一次确认。选 2 张时两张的差异：

- 第 1 张 · 强标题：标题占比最大，主体辅助（清单卡片构图）
- 第 2 张 · 强氛围：场景与色彩更突出，但标题仍然清晰（背景大字构图）

**尺寸**：固定 **1K / 3:4 = 864×1152**。导出时统一渲染成封面标准 **1080×1440** —— 底图会被放大 1.25 倍（背景照片基本看不出），而**文字是按 1080 宽实时绘制的，永远是矢量清晰**，不受底图分辨率影响。

**出图结果的显示**：Agnes 把图放在 `storage.googleapis.com` 上，正常直连就能显示；万一 CDN 查 Referer 导致加载失败，前端会自动改走 `GET /api/image/proxy` 重试 —— 和视频那条链路同一套兜底思路。

**密钥**：和「笔记拆解」共用「设置 → Agnes 密钥」里启用中的 Key（同一套轮换策略），服务端依旧**不持有任何密钥**。

### 文字乱码怎么办：无字底图 + 网页叠字

AI 出图里的中文常常是乱码 / 缺笔画 / 多出怪字。**这不是提示词没写好的问题，是原理问题**：扩散模型不是排字机，它生成的是「看起来像字」的像素图案。一个汉字十几个笔画，几个字挨在一起笔画就糊成一团。英文和数字笔画少，所以常常能活下来 —— 中文基本无解，靠调提示词救不回来。

所以文字一律走 **「无字底图 + 网页叠字」**，没有第二个选项：

- 提示词里明确要求「**这张图里不能有任何文字**」，并预留一块干净的标题区；
- 出图后由浏览器用系统字体（PingFang SC）把标题画到 canvas 上。

> 曾经提供过「AI 直接画字」（提示词里逐字列出标题 + 要求「中文笔画完整、无乱码」）作为备选，  
> 已按用户要求**移除** —— 它对中文本来就不可靠，留着只会让人误以为是个可行选项。

这套做法的细节：

- **所见即所得**：预览（540×720）和导出（1080×1440）走的是**同一个绘制函数**，字号按 1080 宽定义再等比缩放，所以预览什么样、导出就什么样，不会错位。
- **自动裁掉底图自带的边**：模型经常把画面缩在中间、四周留一圈纯色边（最常见是左右两条白边），这种边铺满后还是白的。加载底图时会自动量四条边上的纯色带并裁掉 —— **只裁单轴的边**：左右有边就裁左右，上下有边就裁上下；**四条边都有则不裁**（那多半是「专业简约」这类白底设计稿，动了会毁版式）。裁了会在结果下方注明「已裁掉底图自带的边（左右各 N / N px）」。
- **提示词里也明确要求铺满**：写了「★ 背景必须铺满整张图：底色和场景一直延伸到四条边，不留白边、黑边、描边框或圆角留白」。注意早期版本这里写的是「画面保留约 20% 留白」——`留白` 这个词模型会照字面理解，直接给你留出白边，所以改成了「画面内保留约 20% 的呼吸空间（不是四周的白边）」。
- **自动适配字号**：最长一行超出安全宽度（左右各留 7.5%）时自动等比缩字号，不会让文字冲出画布。缩了会在字号旁边提示「最长一行放不下，已自动缩到 N」。
- **底图必须是同源**：canvas 画过跨域图片后再导出会抛 `SecurityError`（画布被「污染」）。所以底图一律走本机代理 `/api/image/proxy` 或 `data:` 内联，不走 Agnes 的原始 CDN 地址。
- **导出**：点结果下方的「导出 PNG」直接存 1080×1440 的图，已经是小红书封面标准尺寸，不用再缩。

> 这也是 `space-xhs-cover` skill 第 7 步自带的后备方案：「同一文字连续两次仍无法准确生成时 → 生成无字底图并预留明确标题区 → 转用 `xhs-html` 完成逐字准确的文字排版」。这里把它做进了页面里。

### 标题生成（Agnes 对话模型）

把 `space-xhs-title` 那套流程做成了界面上的三张卡片：

| 卡片        | 内容                                                                        |
| --------- | ------------------------------------------------------------------------- |
| 1 · 你要做什么 | 模式（**给主题起标题** / **优化现有标题**）+ 内容类型（11 类，来自 skill 的「按内容类型路由方法」表，决定优先用哪几种方法） |
| 2 · 内容    | 笔记主题 / 草稿 / 要点；选填「目标人群」「想押的搜索词」。写具体点（真实价格 / 时长 / 条目数）标题会明显更强              |
| 3 · 生成    | 候选数量 **12 / 20 个**，一键出结果                                                  |

**核心原则**：小红书标题同时干两件事 —— 在信息流里被划过时抓住人（情绪 + 人群 + 缺口）、在搜索框里被搜到（关键词命中）。只做到第一件的标题活三天，两件都做到才吃半年长尾。

结果按 skill 的输出格式分成五块：

1. **① 内容标题简报** —— 目标人群及自称词、候选搜索词、核心对象、最大爆点、可用证据、事实与合规边界。
2. **② 候选标题矩阵** —— 表格逐条给：标题 / **字符数** / 方法 / **押的搜索词** / 评分 / 风险。超 20 字的标红（平台会截断）；中高风险写明原因。每行一个「复制」。
3. **③ Top 5 推荐** —— 按用途分角色：**综合首选 / 搜索版 / 爆点版 / 收藏版 / 稳健版**，不是按分数机械排。
4. **④ A/B 测试建议** —— 每组只改一个变量，并写清看哪个指标（点击率 / 搜索进入占比与 7 天长尾曝光 / 收藏率）。
5. **⑤ 配套提示** —— 核心搜索词是否也进了正文首句和话题标签。

**15 种方法**（模型按内容类型挑）：人群标签前置 / 搜索词卡位 / 数字清单+收藏指令 / 避雷劝退 / 后悔体 / 情绪惊叹 / 亲测对比 / 保姆级教程 / 反常识纠错 / 悬念缺口 / 场景具体化 / 平替省钱 / 时间承诺 / 求助提问 / 节点热点。

**评分**：百分制（内容兑现度 20 / 搜索词覆盖 15 / 人群指向性 15 / 情绪与钩子 12 / 收藏动机 10 / 具体性 10 / 字数与节奏 8 / 口语与平台感 5 / 独特性 5）。超 20 字符、正文兑现不了、捏造数字价格亲测、触碰违规红线 —— **直接淘汰**。

**合规红线**（写进提示词，不靠模型自觉）：医疗功效断言、绝对化用语、收益投资承诺、点名贬损、导流指令、敏感擦边，一律不碰。

**为什么提示词放服务端**：15 种方法 + 评分表 + 违规红线一共两三千字，每次请求都传一遍纯浪费；前端只传「用户填了什么」（`POST /api/title/generate`），提示词在 `server.js` 里。

**密钥**：走对话模型（`agnes-2.5-flash`）；共用「设置 → Agnes 密钥」里启用中的 Key。

**改写模式**的额外规矩：先诊断原标题（有没有可搜索的名词 / 字数是否超限 / 有没有人群指向 / 是否公众号腔），保留原标题里已经有效的部分，再分三类改写 —— 稳健优化 / 换方法重写 / 激进测试。不要把「更夸张」当成唯一优化手段：很多标题的问题不是不够刺激，而是一个词都搜不到。

### 网络错误为什么能看出真因

Node 内置的 `fetch`（undici）失败时只会给一句 `fetch failed`，真正的原因藏在 `e.cause` 里  
（`ENOTFOUND` / `ECONNREFUSED` / `ERR_TLS_CERT_ALTNAME_INVALID` …）。只打 `e.message` 的话，  
界面和日志都只剩「连不上 xxx：fetch failed」，分不清是 DNS 解析错、证书不对、还是对方没开机。

`neterr.cjs` 的 `rootCause(err)` 会剥到最里层（`AggregateError` 取 `.errors[0]`，`cause` 递归），  
把错误码翻成中文，所有面向用户的网络错误文案都走它。

> 2026-10-06 实际踩过：本地 DNS 把 `api.agnes-ai.cn` 解析到了一台「证书里只有 IP、没有域名」的服务器  
> → 报 `ERR_TLS_CERT_ALTNAME_INVALID`，表现为**时好时坏**（换到解析正确的 IP 就正常），  
> 但界面只显示 `fetch failed`。根因是路由器下发的 DNS 结果不稳定，  
> 已改成手动指定公共 DNS（`networksetup -setdnsservers Wi-Fi 223.5.5.5 119.29.29.29`）解决。  
> 恢复自动获取：`networksetup -setdnsservers Wi-Fi Empty`。

## 视频为什么可能放不出来

报告里点封面上的 ▶ 会开居中弹窗播放视频。**小红书 CDN（`xhscdn.com`）会检查 Referer**：  
从 `127.0.0.1` 页面直连时浏览器会带上 `Referer: http://127.0.0.1:8090/`，被 CDN 判成「外站引用」→ 403，  
表现就是**一块黑屏 + 播放图标，什么提示都没有**。（封面图早先就靠 `referrerpolicy="no-referrer"` 绕过去了，  
视频这条路径当时漏了。）

现在有三层：

1. **页面整体声明 `no-referrer`**（`<meta name="referrer" content="no-referrer">`）——  
   视频 / 图片请求干脆不带 Referer，治本。
2. **直连失败自动改走本机代理** `GET /api/xhs/media?u=<直链>` —— 服务端去取，同样不带 Referer，  
   并把 `Range` 转发过去（所以进度条能拖）。代理带**域名白名单**（只放行小红书系 + 红狐），  
   因为本服务带 `Access-Control-Allow-Origin: *`，不设白名单就等于给任意网页开了一个能打内网的本地代理。
3. **两条路都不通就把真因显示出来**：把上游的 HTTP 状态（403 = 防盗链 / 已过期，404 = 直链失效）  
   或浏览器的 `MediaError` 码翻成人话，连同「新窗口打开直链」「复制直链」两个按钮一起给出来，  
   **不再是一块什么都不说的黑屏**。

> 直链是**带时效**的。如果是过期，唯一解法是回「解析短链」重新跑一次这条笔记拿新链接。

## 已知边界

- **红狐每次调用都消耗积分**：每篇要调 1~2 个接口，视频笔记转写再调一次。红狐**邮箱注册即送 200 积分**，用完了换个新邮箱再注册一个账号就行。建议先用隐藏的 `xhsProvider: "mock"` 验证链路，确认无误再切回 `redfox`。
- **只有红狐一家，没有备用源**：红狐挂了就只能用 `mock`。界面上不再有多厂商切换。
- **视频笔记拿不到配图**：`parseWork/parse` 对视频返回的是无水印直链，实测 `imageUrls` 为空、只回一个 `cover`（封面再走详情接口 / 页面兜底补）。所以报告里「配图」区只对**图文**笔记展示 —— 视频走封面播放按钮 + 弹窗。
- **分享链接的 token 会失效**：取不到内容时，在 App 里对该笔记**重新复制链接**再试。
- **转写失败大多是上游抽风**：RedFox 偶发 `解析小红书作品信息异常`，同一链接「时好时坏、有几分钟窗口期」，重试即可，不用改请求头。
- **红狐接口会变**：改字段/改地址时，只改 `providers.cjs` 里的 `redfox` 对象，上层不动。
- **网络报错先看真因**：出现「连不上 xxx」时，后面的括号里就是真因（DNS / TLS 证书 / 拒绝连接 / 超时）。  
  如果报 TLS 证书域名不匹配，多半是**本机 DNS 解析到了错误的服务器**，换个公共 DNS 即可（见上面「网络错误为什么能看出真因」）。
- **封面制作：出图走的是独立链路**：Agnes 出图模型和「笔记拆解」的对话模型是两次不同的调用，选 2 张就是 2 次出图。
- **封面制作暂时不做 img2img**：还不能上传实拍主体 / 背景 / 参考图，只能从零生成。另外也没有落盘保存 —— 结果只存在浏览器里，要留就点「导出 PNG」。
- **文字不交给模型画**：扩散模型「画」字对中文不可靠，这是原理限制、不是 bug，所以不提供「让 AI 直接画字」这个选项。
- **标题生成：模型偶尔不听话**：`count` 只是「要求」，模型可能给不到 20 条；超 20 字符的候选会**标红但不丢弃**（丢掉会让 12 条变 8 条，用户宁可自己删）。评分和风险由模型自评，最终仍要你自己过一遍合规。
- **仅供个人分析**：请遵守平台条款，勿用于批量采集或二次分发他人内容。
