# RedBuddy · 小红书洞察工具

本地运行的小红书内容提取 / 分析工具 —— 贴一条分享短链，自动出**拆解报告**；也能**出封面**、**批量起标题**。

**不需要登录、不需要扫码**，全部在本机跑。本仓库既是 **WorkBuddy AI 技能包**，也是**完整可交付的应用本体**。

---

## 这个仓库怎么用

| 你是 | 怎么做 | 装到哪 |
|---|---|---|
| **在用 WorkBuddy AI** | 把整个仓库目录拷到 `~/.workbuddy-ai/skills/redbuddy/`，之后直接说「帮我打开 RedBuddy」 | AI 会帮你装到 `~/RedBuddy` 并起服务 |
| **只想用这个工具** | 下载仓库 → 跑一次 `bash scripts/install.sh` → 双击应用目录里的「启动.command」 | 默认 `~/RedBuddy` |

两条路装出来的东西**完全一样**，技能包只是多了一层「帮你装、帮你起、帮你开」的自动化。

## 快速开始（手动）

**前置只有一个：Node.js 18 或更高版本**（[nodejs.org](https://nodejs.org) 下 LTS 即可）。
本项目**零第三方依赖** —— 不需要 `npm install`，不需要 Playwright / ffmpeg / 本地 Whisper。

```bash
git clone https://github.com/MrPlusZhao/redbuddy.git
cd redbuddy

bash scripts/install.sh          # 默认装到 ~/RedBuddy，也可以 bash scripts/install.sh /自定义/路径
bash scripts/start.sh            # 起服务，就绪后自动打开浏览器
bash scripts/stop.sh             # 停止
```

装好之后**日常只需要「启动」这一步**：

- **macOS** —— 双击 `~/RedBuddy/启动.command`
- **Windows** —— 双击 `~/RedBuddy/启动.bat`
- 或者直接 `cd ~/RedBuddy && node server.js`

然后打开 <http://127.0.0.1:8090/> 就能用了。

> `scripts/serve.sh` 是 `start.sh` 的**前台常驻版**，给进程管理器 / AI agent 用 ——
> `start.sh` 是 `node server.js &` 甩后台就退出，从 agent 终端起的后台进程会随回合被回收。

### 平台

| | 状态 |
|---|---|
| Node 代码（4 个 js） | ✅ 全平台，无 `child_process`、无平台分支 |
| 中文字体 | ✅ 字体栈已带 `Microsoft YaHei` / `PingFang SC`，封面叠字不乱码 |
| 启动脚本 | macOS `.command` · Windows `.bat`（功能对齐：`chcp 65001` 防乱码、清代理变量、自动开浏览器） |
| 手机浏览器 | ⚠️ 前端已适配，但服务默认只监听 `127.0.0.1`；要手机访问需改 `config.local.json` 的 `host` 为 `0.0.0.0`（**会把 API Key 一起暴露给同网段设备，想清楚再改**） |

## 需要两个账号（都只要邮箱，都免费）

工具本身不含任何 AI 能力，分析走的是两个第三方服务：

| 账号 | 负责 | 怎么注册 |
|---|---|---|
| **Agnes AI** | 拆解报告、出封面底图、起标题、仿写 | **邮箱注册**即可 |
| **红狐数据 RedFox** | 取小红书内容（标题/正文/配图/互动数）、视频转写 | **邮箱注册送 200 积分** |

红狐积分用完了**换个新邮箱再注册一个**就行。设置页支持配**多个 Key**，
把轮换策略设成「顺序轮换」，一个用完自动换下一个。

**哪些操作不花钱**：启动、看拆解库、改封面参数、看标题 —— 只用本机。
封面样图库那 12 张是**已内置的成品**，不用重新出图。

> 具体每次操作走哪个服务、大概消耗多少，见 `references/使用说明.md`。

## 🔑 密钥不在这个仓库里

**配置文件里不写任何密钥。** RedFox / Agnes 的 Key 只在浏览器「设置」页里配：

- 存在浏览器 `localStorage`（`redbuddy.redfox.v1` / `redbuddy.agnes.v1`）
- 随每次请求传给本机后端
- 服务端**不读环境变量、不读配置文件、不落盘**

没配 Key 也能启动，只是到取数 / 分析那一步会返回明确的 400，提示你去设置里填。

`scripts/install.sh` 首次生成的 `config.local.json` 里**只有端口 / 监听地址 / 数据源 / 模型名这类运行参数**，没有任何密钥字段。
（这份文件本身**不在仓库里**，是安装时生成的；删掉它也能跑，所有字段都有默认值。）

> 历史包袱：早期版本支持过「配置文件 / 环境变量兜底」，结果被 stale 的 Key 静默带偏过好几次
> （曾有一个失效的旧 Key 一直盖住新 Key，表现为「明明换了新 Key 还是报错」）。2026-10-06 整体移除，只留「设置页」一条来源。

## 三个必踩的坑（提前说，能省很多来回）

**1. 必须用「分享短链」**
数据源是按链接取内容的。用小红书 App 里「复制链接」得到的 `https://xhslink.cn/o/xxxxx`，或者直接贴整段分享文案。
只给 24 位笔记 ID 经常打不开 —— 不是工具坏了。

**2. 别带着代理变量启动服务**
Node 的 `fetch` 会走 `HTTP_PROXY` / `HTTPS_PROXY`。如果这俩指向本地代理，访问 `api.agnes-ai.cn` 会 **TLS 证书校验失败**，
症状是「连不上：fetch failed」—— 而 RedFox 却正常，很容易误判成 Agnes 的问题。
两个 `.bat` / `.command` 和 `scripts/*.sh` 都已自动清掉；手动 `node server.js` 时请自己确认：

```bash
env -u HTTP_PROXY -u HTTPS_PROXY -u http_proxy -u https_proxy node server.js
```

**3. 视频直链是带时效的**
它只是一张「临时通行证」，不是视频本身。过期后播放会失败，回「爆款拆解」用短链重新解析这条笔记即可。

## 几个设计上的取舍

**文字不交给 AI 画。** AI 出图里的中文常常乱码 / 缺笔画 —— 这是原理问题不是提示词问题：扩散模型生成的是「看起来像字」的像素图案，一个汉字十几个笔画，挨在一起就糊了。
所以一律走 **「AI 只出无字底图 + 浏览器用系统字体把标题画上 canvas」**，没有第二个选项。预览和导出走同一个绘制函数，所见即所得。

**长任务进度由前端自己维护**，不轮询后端。等待期间轮播一句说明 + 显示已等待秒数。

**服务端不落盘。** 视频 / 图片都不存在本机，本机只存「地址」（在浏览器 `localStorage` 里）。
媒体代理是边拉边转发，没有任何 `writeFile`。

**媒体代理带域名白名单。** 因为本服务的 CORS 是 `*`，不设白名单就等于给任意网页开了一个能打内网的本地代理。

**只保留 RedFox 一家数据源。** 平台不采集浏览器登录态、不绕过登录；内容一律由第三方数据源返回。

## 已知边界

- **红狐每次调用都消耗积分** —— 每篇 1~2 个接口，视频笔记转写再调一次。
- **视频笔记拿不到配图**：数据源对视频只返回一个封面，所以报告里「配图」区只对**图文**笔记展示。
- **分享链接的 token 会失效**：取不到内容时，在 App 里重新复制链接再试。
- **封面制作暂时不做 img2img**：还不能上传实拍主体 / 参考图，只能从零生成；结果也不落盘，要留就点「导出 PNG」。
- **标题生成的 `count` 只是「要求」**：模型偶尔给不到 20 条；超 20 字的候选会标红但不丢弃。评分与风险由模型自评，最终仍要自己过一遍合规。
- **仅供个人分析**：请遵守平台条款，勿用于批量采集或二次分发他人内容。

## 环境自检

```bash
curl --noproxy '*' http://127.0.0.1:8090/healthz
curl --noproxy '*' http://127.0.0.1:8090/api/xhs/env
```

> `--noproxy '*'` 是给走系统代理的机器用的：不清代理的话 curl 连不上 `127.0.0.1`。
> Windows 的 cmd 要写成 `"*"`（双引号），PowerShell 里要显式用 `curl.exe`。
